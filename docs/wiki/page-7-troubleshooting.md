# Page 7: Troubleshooting

Previous: [What to Edit](page-6-what-to-edit.md)
Next: [Release and CI Flow](page-8-release-and-ci-flow.md)

This page explains common failures and what to do first.

## Invalid Repository Root

Failed command:

```bash
python tools/horoji/cli/horoji --repo-root docs get-context horoji_cli
```

Likely meaning:
`docs` is not the repository root. Horoji expects `--repo-root` to point at
the directory that contains `.project_memory/`.

Repair path:

```bash
python tools/horoji/cli/horoji --repo-root . get-context horoji_cli
```

What not to do:
Do not rely on the current working directory as hidden authority.

## Missing `.project_memory`

Failed command:

```bash
python tools/horoji/cli/horoji-check --repo-root /tmp --auto-diff
```

Likely meaning:
The command is running against a directory that is not a Horoji repository, or
the repository bootstrap layout is missing.

Repair path:

```bash
python tools/horoji/validators/validate-all
```

Check that `.project_memory/` exists under the repository root.

What not to do:
Do not create partial memory folders by hand without following the repository
layout.

## Malformed Metadata

Failed command:

```bash
python tools/horoji/validators/validate-all
```

Likely meaning:
An authoritative or derived YAML/JSON file is not shaped correctly. The
validator output should name the file or field.

Repair path:
Open the named metadata file, fix the malformed field, and rerun:

```bash
python tools/horoji/validators/validate-all
```

What not to do:
Do not suppress validator errors or loosen schemas just to make the command
pass.

## Stale Derived Artifacts

Failed command:

```bash
python tools/horoji/cli/horoji-check \
  --repo-root . \
  --auto-diff \
  --derived-policy committed
```

Likely meaning:
Generated files do not match current repository inputs, or a required derived
artifact was generated but is not committed yet.

Repair path:
Run `git status --short`, inspect `.project_memory/derived/**`, and commit the
expected generated artifact when it was produced by Horoji orchestration.

What not to do:
Do not manually edit derived files to make the diff disappear.

## Unsupported Public CLI Command

Failed command:

```bash
python tools/horoji/cli/horoji --repo-root . regenerate
```

Likely meaning:
The command is not part of the small public CLI surface.

Repair path:

```bash
python tools/horoji/cli/horoji --help
```

Use the documented query and validation commands.

What not to do:
Do not document or rely on public `horoji regenerate` or `horoji invalidate`
commands.

## Failed Committed Derived Policy

Failed command:

```bash
python tools/horoji/cli/horoji-check \
  --repo-root . \
  --changed-file README.md \
  --derived-policy committed
```

Likely meaning:
`horoji-check` generated derived changes that are not tracked in the current
commit, or committed derived files are stale.

Repair path:

```bash
git status --short
```

Inspect `.project_memory/derived/**`. If the changes are expected and were
generated by Horoji, include them in the same commit as the source change.

What not to do:
Do not ignore generated files when committed derived policy requires them.

## Failed Validator

Failed command:

```bash
python tools/horoji/validators/validate-all
```

Likely meaning:
One Horoji rule did not pass. The output should include a validator name,
target, reason, and details.

Repair path:
Fix the named artifact or rule violation, then rerun:

```bash
python tools/horoji/validators/validate-all
```

What not to do:
Do not weaken validators to pass a release gate.

## Failed Test

Failed command:

```bash
python -m pytest
```

Likely meaning:
Repository behavior changed or a test expectation is no longer true.

Repair path:
Read the failing test name and assertion. Fix the behavior or update the test
only when the expected behavior intentionally changed.

What not to do:
Do not delete tests to hide behavior drift.

## Changed File Missing Expected Impact Output

Failed command:

```bash
python tools/horoji/cli/horoji-check \
  --repo-root . \
  --changed-file docs/wiki/introduction.md \
  --derived-policy committed
```

Likely meaning:
The changed file may need a derived impact artifact, or impact generation did
not run for the expected primary changed file.

Repair path:
List the source file with `--changed-file`, let Horoji regenerate the expected
derived artifact, and commit the generated artifact if committed policy
requires it.

What not to do:
Do not treat committed derived artifacts as primary impact inputs.
