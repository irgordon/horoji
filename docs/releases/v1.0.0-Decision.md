# v1.0.0 Production Baseline Decision

## Status

Accepted

## Decision

Horoji v1.0.0 is accepted as a stable, governed, repository-resident project
memory subsystem.

This decision does not claim that Horoji is an AI reasoning engine, chatbot,
probabilistic retrieval system, deployment system, release approval authority,
or replacement for repository source files or governance documents.

## Scope

Horoji v1.0.0 includes:

- clean-clone installability
- plain-language README
- developer and user wiki
- stable small public CLI
- schema contract documentation
- release gate documentation
- CI alignment
- authoritative contracts
- authoritative ownership metadata
- authoritative invariants
- deterministic generators
- internal invalidation and regeneration orchestration
- validators
- committed derived policy
- derived provenance
- regression test suite

## Non-Scope

Horoji v1.0.0 does not include:

- public `horoji regenerate`
- public `horoji invalidate`
- autonomous agent control
- natural-language query behavior
- network service
- daemon
- plugin system
- PyPI publishing
- external persistence
- production deployment automation
- source-of-truth replacement
- probabilistic retrieval

## Final Release Boundaries

The final v1.0.0 boundaries are:

- public CLI surface is stable for v1.0.0
- metadata schema surfaces are governed for v1.0.0
- regeneration and invalidation remain internal orchestration
- derived artifacts remain derived
- authoritative files remain the source of project memory truth
- validators remain required release gates
- committed derived policy remains required
- determinism and repository locality remain required
- active tool surfaces require ownership metadata

## Release Decision

Accepted for v1.0.0 production baseline.

The evidence supports acceptance because the public CLI contract, ownership,
determinism, provenance, aggregate validators, regression tests, release docs,
wiki, committed derived policy, and final release boundaries agree. No
release-blocking drift was found during the final audit.

## Caveats

- v1.0.0 is a stable repository-local production baseline, not a hosted
  service.
- Horoji does not replace source files or governance docs.
- The public CLI remains intentionally small.
- Regeneration and invalidation remain internal orchestration.
- Post-v1 improvements remain tracked in the roadmap.

## Follow-On Work

Reasonable post-v1 work may include:

- improve query ergonomics
- add more examples
- expand documentation where users find gaps
- add release automation later if needed
- improve performance if large repositories require it

These items are not part of the v1.0.0 release gate.
